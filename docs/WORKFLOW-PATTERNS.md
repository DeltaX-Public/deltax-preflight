# Workflow problems Preflight can help structure

These are **integration patterns to adapt and test**, not shipped connectors, customer deployments, or guarantees of safety. The same validator can be called through the CLI, GitHub Action, or local MCP server. In every pattern, the proposing actor supplies exact options; the workflow owner controls hard rules; an authorized source supplies facts; and a separate host decides whether and how to act. [Start with the first-check guide](BUILD-YOUR-FIRST-CHECK.md) if those roles are unfamiliar.

| Problem and pause point | Example exact proposal and owner rule | Evidence the workflow must source | What the result changes |
| --- | --- | --- | --- |
| **Coding agent changes a reviewed PR plan.** Pause before accepting a new file, command, dependency, or merge. | Candidate names a file set, operation, and repository head. Owner rule: exact reviewed scope and allowed effect class. | Protected base manifest, current head, and reviewed payload match. | A changed payload becomes unproven; get fresh review instead of treating an unchanged action ID as permission. [Runnable PR-gate recipe](../examples/github-agent-gate/README.md). |
| **Long-running agent resumes after an access change.** Pause before a protected read/write. | Candidate names actor, resource, operation, and current task. Owner rule: current grant and task scope. | Authorized identity/permission source and its observation time. | Missing or stale authority holds the step. Preflight does not itself revoke tokens or enforce the later write. |
| **Release controller has several defensible paths.** Pause before deploy, canary, or rollback. | Candidates include release target and effect. Owner rules: reversible and bounded blast radius. | Current environment, reversibility and blast-radius facts from trusted release controls. | Reject violating paths and preserve an open choice when canary and rollback both pass. [Runnable CI fixture](../examples/ci-deploy.json). |
| **Agent wants to send a message or ticket.** Pause before the outbound tool call. | Candidate includes recipient, channel, exact content reference, and task. Owner rules: in scope and separately approved where required. | Recipient and content verification plus approval from the appropriate source. | A changed recipient or missing approval cannot borrow an earlier receipt. The host still sends, if authorized. |
| **Data agent proposes a write.** Pause before schema or data mutation. | Candidate names dataset, operation, target version, and rollback plan. Owner rules: permitted dataset, retention, and reversible change. | Data catalog, current schema/head, and rollback checks from trusted systems. | Show which rule failed or lacks evidence before a write reaches the data platform. |
| **Security triage proposes closing or escalating a case.** Pause before disposition. | Candidate names case, disposition, and evidence set. Owner rules: severity, ownership, and required review. | Alert and case facts from the security system, including freshness and unresolved signals. | Distinguish a permitted disposition from an unproven one; validation is not detection accuracy. |
| **Procurement agent proposes a purchase.** Pause before checkout. | Candidate names merchant, item, total, refund terms, and payee. Owner rules: spend limit and approved terms. | Current merchant response, price/terms, and spending authority from independent sources. | A price within budget can still fail on changed terms. Preflight does not charge a card or verify a merchant by itself. |
| **Physical workflow proposes actuation.** Pause before effect. | Candidate names movement, equipment, limits, and operating mode. Owner rules: current envelope and required operator approval. | Controller state, limits, and authorized operator record. | Hold unknown or out-of-envelope proposals. This is a design pattern, not a DeltaX robotics implementation or safety certification. |

For each adaptation, document the **specific bad outcome** it is meant to prevent, the exact point of interception, and who owns every fact. Add at least one normal case and one changed-state or missing-evidence case. Avoid making the decision payload itself the evidence source. A team that cannot reliably source a required fact should expect `EVIDENCE_REQUIRED` and improve that source before claiming an enforced gate.

## Choose the integration surface

- **GitHub Action:** appropriate when a proposed pull request action should be checked in CI. The [owner-reviewed gate](../examples/github-agent-gate/README.md) is the runnable example. Make its status check required in branch protection if it must block merge.
- **Local MCP adapter:** appropriate when an agent host can pause before a tool call and submit separate v2 documents. The adapter [exposes three local tools](../mcp/README.md), but the host must control policy, evidence and eventual tool execution.
- **CLI or imported core:** appropriate for another controller that can prepare trusted inputs and handle status/exit codes. See [the README workflow section](../README.md#use-it-in-a-workflow).

The entry surface does not change the validator's trust boundary. A `PASS_SINGLE` result does not itself trigger an effect. A `SELECTION_REQUIRED` result can be resolved by a human or a separately authorized system. The [offline Evaluate bridge](ADR-0003-evaluate-bridge.md) demonstrates a bounded, minimized handoff; it does not call a hosted service. Any future live API or SDK usage must follow its then-current verified contract and separate authorization.

## What to publish as a full recipe

A full recipe should contain: a one-paragraph operator problem; exact candidate payloads; owner policy; facts and producer; the expected `checks` trace; a normal and negative fixture; the host's next-step behavior for all four statuses; the later effect receipt and outcome record; and a stated boundary for what Preflight cannot establish. The PR-gate and CI examples already supply runnable starting points. The remaining patterns above should stay labeled **illustrative** until a matching integration and evidence source are demonstrated. [Learn how to interpret and retain outcomes](RESULTS-AND-OUTCOMES.md).
